Two ways to verify what Docket publishes

Option A is checked by a person every issue. Option B is checked by Claude, with a written process that gets corrected and tightened after every run.

Option A

Human-verified

You or a hired researcher open each funder's official page, confirm the details and sign off. Claude only helps find leads and draft the issue.

  • Claude flags changes and drafts entries with source quotes.
  • A person checks every listing before it goes out.
  • Nothing is published unchecked.
What the site can say"Every listing is checked by hand against the funder's official page."
Option B

Claude-verified, improving each run

Claude reads each official page, extracts the dates and rules, and records the evidence. A written playbook is corrected after every mistake, and a fixed test set shows whether accuracy is getting better.

  • Claude does the checking and keeps the evidence log.
  • A person skims a sample and anything flagged, about 15 minutes.
  • The playbook and test set grow with each issue.
What the site can say"Checked by AI against the funder's official page, spot-checked by a person, with the source linked."

The improvement loop for Option B

Option B is only as good as its process, so the process is written down and changed after every mistake. Claude proposes the changes; you approve them.

1 · RUNClaude follows the playbook file and checks every listing
2 · LOGEvery correction by a person is recorded with the cause
3 · FIXThe cause becomes a new rule in the playbook
4 · TESTThe case is added to a fixed set of known answers; the whole set is rerun
5 · MEASUREAccuracy is compared with the last run before the change is kept

Rules that apply to both

  • Only the funder's official page can confirm a date. Aggregators are leads.
  • Every listing links to the official page and shows the date it was last checked.
  • Claude must quote the sentence each date came from. No quote, no date.
  • Anything unclear (rolling calls, conflicting pages, login portals) goes to a person and is labelled unconfirmed until then.
  • Countdowns are computed from the stored date, never typed in.
  • A wrong listing is corrected within a day and noted in the next issue.

Recommendation

Start with Option B for the first three issues, with a person checking every listing, not a sample. That gives you Option A's trust and builds Option B's test set. Then drop to a sample once the numbers hold. Keep the paid tier's wording honest at each step: say "checked by hand" only while a person is checking every listing.

Time and accuracy figures are planning estimates, not measurements. Confirm every funder date on the funder's own page.
